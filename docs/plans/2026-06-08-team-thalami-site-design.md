## Problem

A team lead wants to *open a URL in a browser* and see what the team has in flight — not clone a Git repo, and not install Obsidian. Today the team hoard is browsable two ways, both insufficient for that audience:

- **Git** — you can read the mirrored markdown, but it's a developer surface.
- **Obsidian + Dataview** (`TeamArcDashboard.md`) — a great live table, but it requires Obsidian and the Dataview/Meta Bind plugins, and the Dataview query does **not** render anywhere else.

This is the v2 "GitLab Pages" item from the tier design, now concrete: render the team hoard to a static, browsable website on each push.

## Inspiration — `hoards/jcressy-notes`

A coworker's vault already does exactly this with **Quartz v4** + **GitLab Pages**:

- `.quartz/` holds a pinned Quartz v4 project (`quartz.config.ts`, `quartz.layout.ts`, `package.json`).
- `.gitlab-ci.yml` runs `npx quartz build` on push to the default branch and publishes `public/` to Pages.
- Folder hierarchy becomes the site's nav + URL structure (Quartz's Explorer mirrors the content tree).
- "What publishes" is an **opt-in `publish: true` frontmatter flag** (a custom `ExplicitPublish` filter).
- Its `DASHBOARD.md` is **Obsidian-only** — no `publish` flag, and Dataview doesn't render server-side; the site's index/nav comes from Quartz, not the dashboard.

## Key insight — our gate already happened upstream

Joel's vault is one person's *source and site*, so he needs a per-note `publish: true` to choose what leaves his private vault. **Our team hoard is different: it is a generated, already-curated projection.** `ws thalami publish` only ever mirrors *published-arc* notes that passed the `#team/<arc-id>` tag-gate and the `#private`/`#noteam` denylist. So:

- The selection gate happened at publish time. A Quartz build over the **team hoard** can render **everything in it** — no second per-note flag (no `ExplicitPublish`; Quartz's default "publish all, minus `draft: true`" is fine, optionally with `RemoveDrafts` as a backstop).
- The team hoard *is* the `content/` directory. Its **User → Arc → Notes** layout maps straight to clean site nav.

## Architecture

```text
team-thalami-cfr/                 (Git repo + Quartz content + Pages build)
  .quartz/                        # pinned Quartz v4 project (config, layout, package.json)
  .gitlab-ci.yml                  # pages job: npx quartz build -> public/
  index.md                       # GENERATED by ws thalami publish — the site landing page
  <user>/                         # e.g. rpraestholm/
    <arc-id>/                     # e.g. silence-service-onboarding/
      <note>.md                   # flattened mirrored notes (v1 flatten fix)
    <host>-thalamus.md            # arc frontmatter (DATA; excluded from the build)
  TeamArcDashboard.md             # Obsidian-only Dataview view (excluded from the build)
```

- **Build/serve:** GitLab Pages CI on push to the team hoard's default branch (`npx quartz build -d .. --output ../public`), modeled on Joel's `.gitlab-ci.yml`. Local preview: `npx quartz build --serve`.
- **Selection:** render everything (no `ExplicitPublish`); the upstream tag-gate is the real gate.
- **Layout → nav:** depends on the **v1 flatten fix** — `User → Arc → Note` becomes the Quartz nav/URLs (`/rpraestholm/silence-service-onboarding/grafana-silence-service-setup`). Preserving PARA folders would leak each publisher's personal layout into the site, so flatten is a prerequisite.

## The Dataview gap — a generated index

`TeamArcDashboard.md` is Dataview, so it won't render in Quartz (same as Joel's `DASHBOARD.md`). The site needs its own landing page. So **`ws thalami publish` gains a second emitter**: a plain-markdown **`index.md`** at the team-hoard root, generated from every user's projection frontmatter — listing each user → their published arcs (id, name, status, `next`, last_touched) → links to that arc's mirrored notes. This is static markdown Quartz renders into the site home.

- The Dataview `TeamArcDashboard.md` is **kept** for teammates who open the hoard in Obsidian, and **excluded** from the Quartz build via `ignorePatterns` (it would otherwise render as a dead query block).
- The per-host `<host>-thalamus.md` projection files are **data, not pages** — also excluded from the build (the index is generated *from* them).
- Status/freshness: the dashboard's decay vibe-icons are Obsidian-only; the generated index shows plain `status` + `last_touched` text. (A fancier site-side status visualization is a later nicety, not v2a.)

Concrete shape (illustrative — the plan finalizes it), generated from each per-host projection's `arcs:` frontmatter + the flattened note files under `<user>/<arc-id>/`:

```markdown
# Team — in flight

## rpraestholm
- **silence-service-onboarding** — CFR hosting of Silence service · _active_ · next: summarize Jun-5 meeting
  - [Grafana Silence Service Setup](rpraestholm/silence-service-onboarding/Grafana%20Silence%20Service%20Setup.md)

## <next teammate>
- ...
```

(Quartz slugifies note paths/filenames into clean URLs, so spaces in note names are fine.)

## Components & changes

- **`templates/hoards/team-thalami/`** — add a pinned `.quartz/` project (config + layout + `package.json`), a `.gitlab-ci.yml` Pages job, and Quartz `ignorePatterns` for `TeamArcDashboard.md` + `*-thalamus.md` + `.publish-manifest.yaml`.
- **`ws thalami publish`** — emit/refresh the generated `index.md` (root, and optionally a per-user `index.md`) from the resolved projection frontmatter, alongside the existing projection + note mirroring.
- **Docs** — a "View it in a browser" section in the quickstart; note the site rebuilds on push to the team hoard.

## Open questions (for the plan)

1. **Index shape** — single root `index.md` (all users + arcs) vs. also per-user `index.md` landing pages. Likely: a root index keyed by user, with Quartz's Explorer handling drill-down. Decide in the plan.
2. **NVIDIA GitLab Pages specifics** — Pages jobs on `gitlab-master` need `tags: [pages]` **and** project-level instance runners enabled (see the reference memory on gitlab-master Pages runner tags); Joel's site lives at a `*.gitlab-master-pages.nvidia.com/...` URL. Access is behind NVIDIA SSO. Confirm the team project has Pages + a `pages`-tagged runner before wiring CI.
3. **Quartz version pinning** — pin to a known-good Quartz v4 (Joel uses v4.5.2) for reproducible builds; document the upgrade path.
4. **`index.md` generation source** — generated purely from the per-host projection frontmatter `arcs:` (no Dataview), so it works headless in CI. Confirm the link targets resolve to the flattened note paths.
5. **Realm-declared clone (Plan 3 overlap)** — teammates need the team hoard cloned to publish into it; the realm-declared-hoard capability (deferred) is the natural pairing. The *site* doesn't depend on it (CI builds from the hoard repo directly), but onboarding does.

## Phasing

- **v2a (this design's target):** Quartz config + Pages CI in the template + the generated `index.md` emitter in `ws thalami publish` → a working browser site rebuilt on push.
- **v2b (later):** theming, site-side status/freshness visualization, full-text search, per-user landing pages if the root index gets large.

## Non-goals

- Replacing the Obsidian Dataview dashboard (it stays, for in-Obsidian users).
- Per-note `publish: true` flags in the team hoard (the upstream tag-gate is the gate).
- Real-time updates (the site is push-rebuilt, like Joel's).
- Auth beyond GitLab Pages defaults / NVIDIA SSO.
